# 運用手順

## 予定の登録

サイト掲載用のGoogleカレンダーに、説明欄も含めて公開できる内容だけを登録します。

- **開館日**は開館時間を時刻付きで入力します。通常の開館日は繰り返しにし、時間が変わる日だけ「この予定」を編集します。
- **休館日**は終日で登録します。臨時休館の日に休館の予定を足すと、その日の開館の予定は表示されません。開館・休館のどちらも登録しない日は、開館状況が出ません。
- **催し**のタイトルは「設定 → Museum Calendar」の「予定の種類と英語での表示」に合わせます。催しの固有名や詳細は説明欄に、リンク先はURLだけの行に書きます。「種類が未定義の予定名」に出たタイトルは、入力を直すか、管理者が表に追加します。

通常の反映は約15分ごとです。すぐに確認するには「設定 → Museum Calendar」の「今すぐ更新」を押し、月間カレンダーと照合します。WP-Cronはアクセス時に動くため、アクセスの少ないサイトで定期実行が必要ならサーバーのcronから起動します。

## ステージングへの配備

mainへのpushで「Calendar checks」が通ると、「Deploy to staging」がプラグインのZIPを上書きします。配備先はリポジトリ変数 `STAGING_URL`、ログイン情報はシークレット `STAGING_WP_USER` と `STAGING_WP_PASSWORD` に設定します。トップページには両方のショートコードが必要です。

配備に失敗したら、Actionsの実行ログでプラグインの版、登録状況、手動更新、トップページ表示のどこで止まったかを確認します。手元から再実行するには、上記の環境変数を設定し、`npm run package` の後に `node scripts/deploy-staging.mjs dist/museum-calendar-<版>.zip` を実行します。

### 実サイトのトップページの写し

テーマの写しはGit対象外です。先に[開発環境で表示を確認](development.md#実サイトのトップページ)します。

- 初回は `npm run site:package` で生成したテーマZIPを「テーマのアップロード」で入れ、`dist/site-seed.zip` をプラグインとして有効化します。テーマが有効になり、固定ページ `top` と `en` の不足分が作られます。作成後はこのプラグインを無効化します。
- 更新時はステージングのURLとログイン情報を環境変数かGit対象外の `.env` に設定し、`npm run site:deploy` を実行します。テーマを上書きし、日本語の `/` と英語の `/en/` を検証します。
- 写しを外すにはテーマをTwenty Twenty-Fiveに切り替え、「設定 → 表示設定」で元のフロントページを選びます。

## 本番サイトの切り替え

旧古河邸サイトの切り替えは手動です。先にステージングで切り替えと復旧を試します。

1. 本番のファイルとDBをバックアップして復元を確認し、現在のテーマをZIPで保存します。接続後のDBバックアップには非公開URLの秘密の部分が平文で入るため、アクセスを制限します。
2. 本番用のカレンダーに当月以降の予定を登録し、現在のサイトと照合します。[導入手順](../README.md#インストール)に従ってプラグインを有効化し、カレンダーを接続します。最終取得日時と「種類が未定義の予定名」を確認します。
3. 旧プラグインを有効にしたまま、ステージングで確認したテーマの変更を反映します。対象は両言語のショートコード、月間・本日のテンプレート、予定の詳細とリンクを表示するCSS・JavaScript・PHPです。
4. ページキャッシュを使う場合は `/` と `/en/` の有効期間を15分以下にするか対象から外し、既存のキャッシュを消去します。
5. ログアウトしたPCとスマホで両言語の開館状況・時間、月送り、予定の詳細とリンクを確認します。日付の詳細はキーボードでも開閉できることを確認します。問題がなければ旧プラグインは無効化し、復旧用に残します。翌日、本日の表示が切り替わったことを確認します。

### 元に戻す

1. 旧プラグインを有効に戻し、保存したZIPでテーマを復元します。
2. ページキャッシュを消去し、両言語で元の表示を確認します。切り替え中に旧プラグインへ入力していなかった予定は手入力で補います。
3. Museum Calendarを無効化します。再度使うための設定と取得済みの予定は残ります。不要になりプラグインを削除すると、これらもDBから消えます。

DB移行を伴う更新で差し戻す場合は、更新前のDBとファイルを一緒に復元します。

## 非公開URLの漏えいとリセット

1. Googleカレンダーの「設定と共有 → カレンダーの統合」で「iCal形式の非公開URL」をリセットします。
2. すぐに新しいURLをWordPressの「設定 → Museum Calendar」に貼り付けて保存し、最終取得日時が更新されて「取得失敗」が出ていないことを確認します。

Google Workspaceで非公開URLが表示されない場合は、組織の管理者に利用を依頼します。公開可能な専用カレンダーなら、一般公開で「すべての予定の詳細を表示」を選び、「iCal形式の公開URL」を登録する方法もあります。

## 予定の種類の表の復旧

「設定 → Museum Calendar」で「既定の表に戻す」を選んで保存します。管理画面を開けない場合は、WP-CLIで `wp option delete museum_calendar_kinds` を実行すると既定の表に戻ります。
